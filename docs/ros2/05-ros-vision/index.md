### 1.2 数字图像的本质

**人眼看到的是风景，机器看到的是矩阵。** 一张图像就是函数 f(x, y) 映射出的矩阵：

- **Image = Matrix**，尺寸 `H × W × C`。
- **Pixel（像素）**＝矩阵中的一个元素，8 位整数：**0 表示黑，255 表示白**。

![数字图像：幕后的矩阵](./images/p005-01.webp)
![Image = Matrix](./images/p006-02.webp)

图像坐标系有讲究：**原点在左上角 (0,0)，Y 轴向下**。访问像素用 `img[y, x]`（行、列），**不是** `img[x, y]`。

![图像坐标系](./images/p007-03.webp)

彩色图像有**通道（Channels）**，每个像素是一个向量 `[c1, c2, c3]`。

> [!WARNING] OpenCV 的历史包袱
> OpenCV 默认按 **BGR** 读取，而标准（如 Matplotlib）期望 **RGB**。追踪前务必转换，否则颜色会错乱。

```python
import cv2
img_bgr = cv2.imread('red_car.jpg')
img_rgb = cv2.cvtColor(img_bgr, cv2.COLOR_BGR2RGB)
```

![通道 Channels](./images/p008-04.webp)
![BGR vs RGB](./images/p009-05.webp)

**要点回顾**：图像是矩阵、原点在左上且 Y 向下、访问用 `img[y,x]`、OpenCV 用 BGR。

![关键要点回顾](./images/p010-06.webp)

> 思考题：如果把一张图的 G 通道全部置 0，图片会变成什么色调？

### 1.3 颜色几何学

**RGB 的软肋**：同一个红球，光照变暗后 R/G/B 三个值全部下降，坐标全变了，无法稳定追踪。

![光照的恶作剧](./images/p012-07.webp)

**换一种视角：HSV。** 把颜色从"立方体"映射到"圆柱/圆锥"：

| 分量                       | 含义                 | 几何        |
| -------------------------- | -------------------- | ----------- |
| **H（Hue 色相）**          | 颜色类型（身份证）   | 角度 0–360° |
| **S（Saturation 饱和度）** | 纯度，加了多少"白漆" | 半径        |
| **V（Value 亮度）**        | 明暗，加了多少"黑漆" | 高度        |

![HSV 几何](./images/p013-08.webp)
![Hue 色相](./images/p014-09.webp)
![饱和度与亮度](./images/p015-10.webp)

> [!CAUTION] OpenCV 特有的坑
> 数学上 H ∈ [0, 360]，但 OpenCV 的 uint8 里 **H ∈ [0, 180]**，即 `OpenCV_Hue = 数学_Hue / 2`。

**鲁棒追踪的核心——只锁 H**：H 严格限制范围，S 宽泛，V 极其宽泛（忽略阴影和高光）。

```python
mask = cv2.inRange(hsv, lower_red, upper_red)
```

![只锁 H](./images/p016-11.webp)
![色彩空间与追踪要点](./images/p017-12.webp)

### 1.4 掩膜与形态学

**掩膜（Mask）**：用 `cv2.inRange` 把彩色图变成黑白分明的二值图——白色 255 是感兴趣区（ROI，物体），黑色 0 是背景。

![什么是掩膜](./images/p019-13.webp)

现实很骨感：掩膜里会出现**椒盐噪声**（传感器热噪声、光照闪烁、压缩伪影）。

![噪声](./images/p020-14.webp)

两把手术刀：

| 操作               | 逻辑                             | 作用                  |
| ------------------ | -------------------------------- | --------------------- |
| **腐蚀（Erode）**  | 与逻辑，核内有一个黑，中心就变黑 | 消除小噪点（islands） |
| **膨胀（Dilate）** | 或逻辑，核内有一个白，中心就变白 | 填补空洞、连接断裂    |

![腐蚀](./images/p021-15.webp)
![膨胀](./images/p022-16.webp)

**完美组合拳——开运算（Opening）＝ 先腐蚀再膨胀**：去噪的同时保持物体大小。

![开运算](./images/p023-17.webp)

### 1.5 图像几何定位

机器人看不懂"形状"，它只想要一个**坐标 (x, y)**。

![给机器人一个靶心](./images/p025-18.webp)

核心原理：**求所有白色像素的"平均住址"（质心）**。

![平均位置](./images/p026-19.webp)

OpenCV 的"自动计数器" `cv2.moments()` 会返回：`m00`（面积）、`m10`（X 坐标总和）、`m01`（Y 坐标总和）……我们只负责最后一步除法：

```python
M = cv2.moments(mask)
if M["m00"] != 0:
    cx = int(M["m10"] / M["m00"])
    cy = int(M["m01"] / M["m00"])
```

![cv2.moments](./images/p027-20.webp)

## 二、ROS 的视觉管理

### 2.1 工程思维的转变

不要写"单体脚本（main.py）"把采集、处理、发送全塞在一起——难以维护、调试和扩展。

要拆成**解耦系统**：相机驱动 → 图像主题 → 视觉节点 → 处理结果，模块化、可复用、可测试、可扩展。

![工程思维的转变](./images/p030-21.webp)

### 2.2 摄像头节点

```bash
# 测试虚拟机摄像头
sudo apt install cheese
# 安装 usb_cam 驱动
sudo apt install ros-jazzy-usb-cam
# 运行摄像头节点
ros2 run usb_cam usb_cam_node_exe
# 用 rqt 查看图像
ros2 run rqt_image_view rqt_image_view
```

> 记得在虚拟机里配置 **USB 3.1** 才能直通摄像头。

### 2.3 CvBridge：不同内存空间的桥接

ROS 消息（序列化的二进制 Blob，用于网络传输）与 OpenCV Mat（结构化数组，用于计算）格式不同，用 **CvBridge** 转换：

```python
import cv2
from cv_bridge import CvBridge

bridge = CvBridge()

def image_callback(msg):
    cv_image = bridge.imgmsg_to_cv2(msg, desired_encoding="bgr8")
    # cv_image 现在是标准的 OpenCV Mat / NumPy 数组
```

![CvBridge](./images/p032-22.webp)

### 2.4 三个递进的视觉节点

| 需求 | 节点             | 工作                                                    |
| ---- | ---------------- | ------------------------------------------------------- |
| 显示 | 原生图像节点     | 订阅数据 → CvBridge 转换 → `imshow` 显示                |
| 框选 | HSV 图像显示节点 | 转换 → HSV 阈值 + 腐蚀膨胀 → 输出 OpenCV 矩阵与物体坐标 |
| 识别 | 物体位置识别节点 | 固定阈值识别物体，**发布位置信息**供其他节点使用        |

## 三、ROS 的坐标转换

### 3.1 机械臂的"借眼抓取"（Eye-to-Hand）

相机拍到红方块，机械臂要把夹爪移到红方块上——这需要把**像素坐标**映射到**物理世界坐标**。关键词：ROS2 TF2、坐标系、空间变换。

![借眼抓取](./images/p037-26.webp)

### 3.2 两个世界的隔阂

- 摄像头看到的：**像素（Pixels）**，如 `(u=200, v=300)`。
- 机械臂理解的：**米（Meters）**，如 `(0.5, 0.3)`。

![两个世界的隔阂](./images/p038-27.webp)

### 3.3 坐标系确立：谁是 (0,0)？

用 `frame_id` 定义父子坐标系：`base_link`（机械臂基座，父，原点 0,0）→ `camera_link`（相机，子，偏移 0.5 米）。

![坐标系确立](./images/p039-28.webp)

### 3.4 第一层挑战：平移

```text
X_final = 0.5（相机位置）+ 0.1（苹果在相机里的位置）= 0.6
Y_final = 0 + 0.1 = 0.1
```

![平移](./images/p040-29.webp)

### 3.5 第二层挑战：旋转的陷阱

相机若被**旋转 90° 安装**，它的"前方 X"其实是机械臂的"左方 Y"的相反方向——直接相加就错了。

| 动作       | 摄像头看来 | 机械臂看来 |
| ---------- | ---------- | ---------- |
| 苹果向右移 | X 增加     | Y 减小     |

![旋转的陷阱](./images/p041-30.webp)

### 3.6 救世主：ROS TF2

用 `static_transform_publisher` 在 launch 里声明相机相对基座的变换，TF 会自动处理平移与旋转：

```python
Node(
    package='tf2_ros',
    executable='static_transform_publisher',
    arguments=['0.5', '0', '0',
               '1.57', '0', '0',      # 绕轴旋转（弧度）
               'base_link', 'camera_link']
)
```

![ROS TF2](./images/p042-31.webp)

### 3.7 实时计算物体在机械臂坐标系中的坐标

三个节点协作：

| 节点                 | 职责                                       |
| -------------------- | ------------------------------------------ |
| 物体坐标识别节点     | 发布物体在**摄像头**中的坐标信息           |
| 物体 TF 坐标转换节点 | 订阅物坐标 + 参考变换，发布 TF 坐标        |
| 机械臂运动节点       | 订阅 TF 坐标，获取物体在**机械臂**中的坐标 |

![实时坐标转换](./images/p043-32.webp)

## 四、正解与反解

### 4.1 什么是运动学（Kinematics）

> 研究物体的运动，不考虑质量和力。

两个空间之间的转换：

- **关节空间（Joint Space θ）**：各关节的角度。
- **笛卡尔空间（Cartesian Space x, y, z）**：末端在世界中的位置。

![运动学定义](./images/p045-33.webp)

### 4.2 正运动学 FK vs 逆运动学 IK

|      | 正运动学 Forward（FK）               | 逆运动学 Inverse（IK）                         |
| ---- | ------------------------------------ | ---------------------------------------------- |
| 方向 | 关节角 θ → 位置 x,y,z                | 位置 x,y,z → 关节角 θ                          |
| 比喻 | **盲人射箭**：角度定了，落点是唯一的 | **篮球投篮**：知道篮筐位置，手臂角度却不止一种 |
| 难度 | 简单、唯一解                         | 难：多解、奇异点、不可达                       |

![FK / IK 比喻](./images/p046-34.webp)

> [!NOTE] IK 的三个难点
> **多解（Multiple Solutions）**、**奇异点（Singularity）**、**不可达（Unreachable）**。

### 4.3 机器人的骨架：URDF

URDF 用线框图描述机器人的骨骼：

- **Link（连杆）**＝质量 + 长度 + 惯性。
- **Joint（关节）**＝旋转轴 + 限制范围。

> URDF 不是代码，它是机器人的 DNA。

![URDF 骨架](./images/p047-35.webp)

### 4.4 父子关系与变换链

`Base`（不动）→ `Shoulder`（随基座）→ `Elbow`（随肩膀）……当 Shoulder 旋转 30° 时，Elbow 及其后的所有坐标系整体跟着转 30°。

> 视觉隐喻：就像一列火车，车头动了，车厢必须跟着动。

![父子关系与变换链](./images/p048-36.webp)

### 4.5 正运动学：向量叠加

把每根连杆看作一个向量，依次"生长"在前一根的末端。

```text
位置 = 向量1 + 向量2 + ……
```

![FK 向量叠加](./images/p049-37.webp)

### 4.6 逆运动学：几何直觉

以基座为圆心、大臂 L₁ 为半径画圆 A；以目标点为圆心、小臂 L₂ 为半径画圆 B。两圆的交点就是肘关节的位置——通常有**两个解**：`Elbow Up` 与 `Elbow Down`。

![IK 几何直觉](./images/p050-38.webp)

### 4.7 多解与奇异点

- **多解**：姿态 A（举手，肘朝上）与姿态 B（垂手，肘朝下）都能抓到同一个点。
- **无解/奇异**：两圆相离 → 够不着（Unreachable）；两圆相切 → **奇异点**，手臂伸直锁死，动弹不得。

![多解与奇异点](./images/p051-39.webp)

### 4.8 FK 输入与过程快照

给关节角（J₁ 基座 90°、J₂ 肩膀 -90°、J₃ 肘部 90°，其余保持 0），机械臂依次变化，最终末端位姿 `x=0.5, y=0.5, z=0.3, Pitch=90°`。

> 链条（Chain）：每一个关节的运动都会改变后面所有关节的位置。

![FK 输入与过程](./images/p052-40.webp)

### 4.9 IK 案例：条条大路通罗马

同一个目标姿态 `x=0.6, y=0.0, z=0.4`（且抓手必须垂直向下），可以有：

- 姿态 A（Elbow Up）：像举重一样，肘部朝上抓。
- 姿态 B（Elbow Down）：像掏东西一样，肘部朝下兜。
- 姿态 C（Lefty/Righty）：基座旋转 180°，反手抓取。

对于标准 6 轴机械臂，通常是 **n 组解**。

![IK 案例](./images/p053-41.webp)

### 4.10 全链路：从像素到动作

```
1. 摄像头节点 ──图像数据──▶ 2. 物体识别节点（输出摄像头系坐标）
   ──▶ 3. 物体坐标转换节点（TF 变换 → 机械臂基座系）
   ──▶ 4. 机械臂抓取节点（URDF 反解 → 关节角）
   ──▶ 5. 机械臂驱动节点 ──▶ 物理执行
```

![全链路](./images/p054-42.webp)

## 本章小结

- **图像本质**：矩阵 `H×W×C`，原点左上、Y 向下，`img[y,x]`，OpenCV 用 BGR。
- **色彩追踪**：用 HSV 分离光照与颜色，**紧 H、松 S/V**。
- **形态学**：腐蚀去噪、膨胀补洞、开运算（先腐后膨）去噪保形。
- **定位**：`cv2.inRange` 出掩膜，`cv2.moments()` 求质心坐标。
- **ROS 视觉**：相机驱动 + CvBridge + 解耦的视觉节点。
- **坐标转换**：TF2 处理平移与旋转，把像素坐标变成机械臂坐标。
- **运动学**：FK/IK、URDF 骨架、父子变换链、多解与奇异点。
